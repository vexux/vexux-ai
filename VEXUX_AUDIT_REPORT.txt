4. API route and fraud-specific call path
-----------------------------------------
CONFIRMED: API
- `api.main.get_agent()` returns `core.composition.create_agent()`.
- `POST /api/v1/agent/run` injects this generic agent through `run_agent()`,
  which calls `agent.run(query, session_id, user_id)`.
- AgentRunRequest accepts optional workflow, agent, and delegations values,
  but `run_agent()` does not forward these fields.
- The generic composition registers KnowledgeGroundedAnswerWorkflow, not
  FraudInvestigationWorkflow. The route therefore does not select the
  synthetic or real fraud composition.
- FastAPI's default interactive documentation path is `/docs`.
- The endpoint emits audit events and redacts some serialized output, but
  does not authenticate the requestor.

CONFIRMED: synthetic fraud path
- `apps.fraud.demo.create_demo_agent()` calls generic composition, then
  creates a temporary SQLite database seeded from
  `apps/fraud/data/sqlite/demo.sql`, creates in-memory graphs, configures
  FraudPolicy, and registers FraudInvestigationWorkflow.
- The direct demonstrated call shape is:
  enter `create_demo_agent()` context, then call
  `agent.run("Investigate C1001", user_id="investigator")`.
- `FraudInvestigationWorkflow.plan_query()` maps recognized fraud queries to
  workflow tasks. The planner and execution manager dispatch them to the
  workflow; the fraud service computes the categorical assessment.
- `Agent.run_workflow()` also invokes a registered workflow directly, but is
  not connected to the HTTP route.
- `apps.fraud.real.create_real_agent()` is a separate Neo4j/MySQL composition
  and intentionally has no synthetic fallback.

6. Fake demo, conditional Neo4j, and RAG downloads
--------------------------------------------------
CONFIRMED
- `create_demo_agent()` defaults to fake only if MODEL_PROVIDER is absent.
  An explicitly selected provider is preserved.
- `core.composition.create_agent()` conditionally constructs a
  Neo4jKnowledgeGraph when config.neo4j_uri is nonempty. This happens before
  create_demo_agent replaces graph registries with synthetic graphs.
- Thus, source-selected demo data is synthetic and does not use a Neo4j
  service, but the demo factory cannot categorically be said to avoid the
  Neo4j package: a nonempty NEO4J_URI can trigger adapter/client construction.
  The effective configuration is unknown.
- The demo path does not construct MySQLBackend. Its data backend is SQLite.
- With fake selected and no Neo4j URI causing construction, the operational
  workflow does not use Ollama, MySQL, Transformers, PEFT, PyTorch, Sentence
  Transformers, or embedding assets.
- FAISS and NumPy remain import-time requirements.
- A RAG retrieval calls RAGPipeline._ensure_initialized(), reads documents,
  embeds them using default `BAAI/bge-small-en-v1.5`, and builds an in-memory
  FAISS index. If the model is not cached, first retrieval may require network
  access to download it.
- ENABLE_LOCAL_RAG_INFERENCE controls local generation in RAGPipeline.ask();
  it does not disable embedding initialization in retrieve().
- Fraud operational requests use the deterministic workflow and do not need
  RAG retrieval. General policy/RAG requests may initialize/download BGE.
- Demo creates a temporary business SQLite file. Fraud workflow audit events
  can initialize local SQLite observability storage at the default
  `data/observability/vexux_observability.db`; audit writes were not run here.

RECOMMENDATION
- For a direct offline synthetic demo, explicitly select fake, ensure the
  effective configuration does not cause Neo4j construction, and restrict
  requests to operational fraud workflow queries. This avoids embedding-model
  download risk but does not remove FAISS/NumPy import dependencies.
