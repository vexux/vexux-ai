2. Demo CLI and actual synthetic case validation
------------------------------------------------
SOURCE-CONFIRMED CLI DISCOVERY
- Before this task, there was no suitable fraud-specific synthetic
  investigation CLI.
- scripts/manual/run_agent.py is an interactive runner built on
  apps.fraud.real.create_real_agent(); it requires the real Neo4j/MySQL

- apps/fraud.demo.create_demo_agent() is the existing synthetic composition.
  The new apps/fraud/demo_cli.py reuses it; it does not create another
  workflow or fixture implementation.

COMMANDS
Run from the repository root in PowerShell:

  .\.venv\Scripts\python.exe -m apps.fraud.demo_cli C1001 --provider fake
  .\.venv\Scripts\python.exe -m apps.fraud.demo_cli C1002 --provider fake
  .\.venv\Scripts\python.exe -m apps.fraud.demo_cli C2001 --provider fake

The positional customer ID is restricted to C1001, C1002, or C2001.
`--provider fake` is the explicit deterministic option and is also the
default/only provider accepted by this synthetic CLI. `main()` temporarily
forces MODEL_PROVIDER=fake, disables Neo4j and generic in-memory knowledge
graph construction, local RAG inference, and autonomous delegation, and
suppresses configured persistent-memory and generic SQL paths. It restores
the prior process environment after the run. The CLI reports success/failure,
investigation output (risk, findings, and resources), and returns a nonzero
exit code for an unsuccessful result.

  `agent.run("Investigate <ID>", user_id="investigator")` succeeded for all
  three IDs using apps.fraud.demo.create_demo_agent().
- The new CLI was then run for all three IDs with `--provider fake`; all
  returned exit code 0 and printed `Status: SUCCESS`.
- Process overrides set NEO4J_URI blank and ENABLE_LOCAL_RAG_INFERENCE=0.
  Temporary observability storage was placed under a task-specific temporary
  directory and removed after the process exited. No database service or
  model provider was contacted by these runs.

3. Architecture, workflow, provider, and RAG
--------------------------------------------
SOURCE-CONFIRMED SYNTHETIC WORKFLOW
- apps/fraud/demo.py:create_demo_agent() calls generic
  core.composition.create_agent(), then replaces its knowledge resources
  with temporary SQLite and in-memory fraud/customer graphs and registers
  apps.fraud.workflow.FraudInvestigationWorkflow.
- agent/agent.py:Agent.run() routes the investigation query into that
  registered workflow. FraudInvestigationWorkflow.run() executes its bounded
  deterministic plan; FraudInvestigationService.build_result() derives the
  categorical assessment from evidence.
- The fraud authorization policy is wired into the synthetic workflow. The
  CLI uses the synthetic actor `investigator`; this is an application actor,
  not proof of an authenticated human identity.

PROVIDER AND QWEN3
- core.contracts.capabilities.ModelProviderContract requires a name and a
  synchronous `generate(prompt, response_format=None, **kwargs) -> str`.
  core.model_gateway.gateway.ModelGateway preserves this provider boundary.
- `fake`, `ollama`, `mistral`, and `qwen` are configured in
  core/config.py. The new demo CLI deliberately selects fake and does not
  alter the default provider configuration.
- models/providers/qwen.py:QwenProvider is an existing Qwen2.5/PEFT-oriented
  Transformers provider, not a Qwen3 implementation.
- Earlier Copilot review was read-only: the loan project's Qwen3 code was
  not found in this repository. A future adapter should preserve the current
  contract, translate model requests/results into Vexux's synchronous string
  response, and be validated with mocked model/tokenizer tests.
- The user-supplied intended Qwen3 asset is a ModelScope cache snapshot at
  `%USERPROFILE%\.cache\modelscope\models\Qwen--Qwen3-0.6B\snapshots\master`,
  with a reported ~1433.66 MB safetensors file and qwen3/bfloat16 config.
  This is USER-SUPPLIED cache evidence, not proof of a loadable model.
- No Qwen3 inference was attempted or succeeded. The approved package source
  and permission to use this cached asset remain UNKNOWN.
- MiniLM embedding support is a separate future change. Do not treat a
  text-generation provider as the RAG embedder.

RAG AND DOWNLOAD RISK
- core.composition.create_agent() constructs a RAGPipeline, but
  rag.pipeline.RAGPipeline initializes its embedder/retriever lazily on
  retrieval. rag.embedder.Embedder defaults to
  `BAAI/bge-small-en-v1.5` and imports Sentence Transformers only when
  loading the embedder.
- The fraud demo CLI invokes the registered fraud investigation path, not
  general RAG retrieval. The CLI also sets ENABLE_LOCAL_RAG_INFERENCE=0.
  The three successful invocations did not initialize embeddings or use
  RAG retrieval. No embedding/model download was triggered by this path.
- RAG retrieval outside this direct workflow may initialize/download the
  configured embedding model if its assets are absent; avoid general RAG
  queries during the synthetic demo.
