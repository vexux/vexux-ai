2. Qwen3 provider and ModelGateway
----------------------------------
SOURCE-CONFIRMED IMPLEMENTATION
- `models/providers/qwen3.py` defines `Qwen3Provider` with the existing
  synchronous `generate(prompt, response_format=None, **kwargs) -> str`
  behavior.
- Model and tokenizer initialization are lazy and cached once per provider
  instance. PyTorch/Transformers are imported only during that initialization.
- The default path is the current user's ModelScope snapshot:
  `~/.cache/modelscope/models/Qwen--Qwen3-0.6B/snapshots/master`.
  A custom path is supported by `QWEN3_MODEL_PATH` or the terminal flag
  `--qwen3-model-path`; `~` and environment-variable paths are expanded.
- Both tokenizer and model use `local_files_only=True`; there is no download
  fallback. The provider explicitly loads and runs on CPU using bfloat16.
- The Qwen3 chat template is used with `enable_thinking=False`. If an older
  tokenizer rejects that specific keyword, the provider retries the template
  without it. It tokenizes with left truncation and a configured input bound.
- Generation uses `torch.inference_mode()`, defaults to deterministic
  decoding, clamps caller output length to the configured maximum, and
  decodes only tokens beyond the input token length.
- `response_format="json"` adds an explicit JSON-only instruction. This is
  prompt guidance; it does not guarantee syntactically valid JSON.
- Loading and generation failures produce explicit `RuntimeError`s with the
  original cause chained. Invalid input, limits, and unsupported response
  formats are rejected; provider errors are not silently replaced by fake.
- The existing `models/providers/qwen.py` Qwen2.5/PEFT implementation was not
  changed or used for Qwen3.

CONFIGURATION AND REGISTRATION
- `core/config.py` now recognizes `qwen3` independently from `qwen`.
- Settings: `QWEN3_MODEL_PATH`, `QWEN3_MAX_INPUT_TOKENS` (default 2048,
  allowed 1..32768), `QWEN3_MAX_NEW_TOKENS` (default 256, allowed
  1..4096).
- Existing provider defaults and configuration remain unchanged. The global
  default provider was not changed.
- `core/composition.py:create_agent()` constructs `Qwen3Provider` when
  `MODEL_PROVIDER=qwen3`; `provider_diagnostic()` and ModelGateway metadata
  identify it as `qwen3`, model `Qwen3-0.6B`, runtime `local`.
- `core.model_gateway.gateway.ModelGateway` and
  `core.contracts.capabilities.ModelProviderContract` were preserved.

3. Existing interactive terminal
-------------------------------
SOURCE-CONFIRMED BEHAVIOR
- The existing terminal remains `scripts/manual/run_agent.py`; no second
  interactive terminal was created.
- Existing input loop, `/actor investigator`, `/actor support_user`,
  progress renderer, provider/runtime banner, `/trace`, `/audit`, `/metrics`,
  and `exit`/`quit` behavior are retained.
- CLI options:
  - `--composition real|synthetic`, default `real`.
  - `--provider fake|qwen3` applies to synthetic mode; absent provider
    defaults to fake in synthetic mode.
  - `--qwen3-model-path`, `--qwen3-max-input-tokens`,
    `--qwen3-max-new-tokens` provide optional Qwen3 overrides.
- Real mode still calls `apps.fraud.real.create_real_agent()` and remains the
  default. Passing synthetic provider/model flags without selecting
  synthetic composition is rejected.
- The banner reads metadata from the actual agent ModelGateway when
  available, rather than assuming it from a separate config value.
- Synthetic input accepts only queries mentioning fixture IDs C1001, C1002,
  or C2001. This keeps the terminal scoped to supplied synthetic cases.

SYNTHETIC SAFETY
- Synthetic mode reuses `apps.fraud.demo.create_demo_agent()` and its
  existing workflow. It does not duplicate investigation composition.
- The terminal temporarily overrides provider and environment settings,
  then restores all prior values on exit, including on exceptions.
- It selects only `fake` or `qwen3`, disables Neo4j/in-memory generic graph
  construction before base composition, disables local RAG inference,
  persistent memory, autonomous delegation, and configured generic SQL.
- It calls `create_demo_agent(enable_rag=False)`. In that mode
  `core.composition.create_agent()` does not construct a RAGPipeline or
  register the generic RAG knowledge source; the execution manager's
  retrieval component is `None`. No embedding initialization/download can
  occur on this path.
- `apps.fraud.demo.create_demo_agent()` provides temporary SQLite fixture
  data and in-memory customer/fraud graphs. It does not invoke
  `create_real_agent()`, Neo4j, or MySQL.
- Provider setup does not alter fraud scoring. A deterministic fraud query
  may not call the language model at all; this is intentional, not a
  missing fallback. The Qwen3 provider is available through ModelGateway
  where normal agent planning/generation uses it.
