4. Architecture, providers, and Qwen3 review
--------------------------------------------
CONFIRMED Vexux interfaces
- `core.contracts.capabilities.ModelProviderContract` is a structural
  Protocol requiring a `name` property and
  `generate(prompt, response_format=None, **kwargs) -> str`.
- `core.model_gateway.gateway.ModelGateway` accepts a provider conforming to
  that Protocol, forwards prompt and generation kwargs synchronously,
  returns a string, logs success/failure metrics, and re-raises failures.
  Its provider metadata allowlist includes provider, model, runtime_mode,
  host, and adapter_path.
- Preserve `ModelProviderContract` and `ModelGateway`.
- `core.config.SUPPORTED_MODEL_PROVIDERS` and
  `core.composition.create_agent()` explicitly enumerate and construct
  supported providers. There is no generic provider plugin discovery.
- Existing providers are fake, Ollama, Mistral, and Qwen. The existing
  `models/providers/qwen.py::QwenProvider` uses Transformers plus PEFT,
  defaults to a Qwen2.5 model identifier, and optionally loads a LoRA
  adapter. It is not a Qwen3-specific provider.
- Copilot completed a read-only Qwen3 integration review. The loan project's
  Qwen3 Transformers implementation is a reference, not code already
  integrated into Vexux. The loan project source was not present in the
  inspected Vexux tree, so its exact `ModelResponse`, request schema,
  async behavior, and error semantics remain unverified here.

QWEN3 LOCAL PROVIDER INTEGRATION REVIEW
--------------------------------------
COPILOT REVIEW / SOURCE FINDINGS
- Vexux's current provider seam is synchronous and string-returning. Any
  loan-project request/response behavior (including a structured
  `ModelResponse`) must be adapted to this contract at the provider boundary:
  accept Vexux's prompt/kwargs and return response text as `str`.
- If the reference implementation is asynchronous, the adapter must
  deliberately bridge that behavior to the synchronous contract; do not
  call `asyncio.run()` blindly in an already-running event loop. Exact
  bridging choice depends on the unavailable reference implementation.
- Map Vexux generation options such as response format, token limits,
  temperature, and sampling settings to Transformers' tokenizer/model APIs.
  Reject or explicitly handle unsupported kwargs rather than silently
  misapplying them.
- Keep provider-specific errors explicit and preserve their causes; avoid
  returning success-shaped fallbacks. Do not include prompt contents,
  credentials, or confidential material in logs or metadata.
- A new provider requires explicit registration in
  `SUPPORTED_MODEL_PROVIDERS`, config parsing/cache snapshot/diagnostics,
  and a `create_agent()` composition branch. Do not change the default
  provider.
- Fraud risk scoring and investigation logic need not change: the
  deterministic scoring implementation consumes evidence/signals and does
  not use the LLM as the risk scorer.

OFFLINE MODEL LOADING PLAN — RECOMMENDATION
- Configure an explicit local model path resolved from the user's
  `%USERPROFILE%` cache location; do not rely on an online model identifier.
- Load tokenizer and model from the local snapshot only, with
  `local_files_only=True` and network-offline controls appropriate to the
  approved Transformers/ModelScope setup. Fail clearly if required files
  are missing; do not fall back to downloading.
- Keep `trust_remote_code=False` unless the company review specifically
  approves required custom code and it is present in the cache.
- Use CPU explicitly rather than `device_map="auto"` for this target.
  Decide bfloat16 versus float32 only after compatibility and memory testing.
- Bound both prompt/input tokens and generated tokens. The config's
  40960-position limit is an upper model limit, not a safe demo target.
  Validate requested limits and reserve space for output within the context
  budget.
- The supplied cache listing does not prove that inference has succeeded.

5. MiniLM embeddings and existing RAG behavior
----------------------------------------------
CONFIRMED SOURCE
- `rag.Embedder` lazily imports Sentence Transformers and currently defaults
  to `BAAI/bge-small-en-v1.5`.
- `RAGPipeline` accepts an injected embedder object with `encode(texts)`;
  it validates that encoded chunks produce a two-dimensional array with
  one vector per chunk. `Retriever` also uses that embedder for query
  encoding.
- `core.composition.create_agent()` currently constructs the pipeline
  without injecting a custom embedder. First retrieval initializes it and
  may download/load the default BGE model if absent.
- Retrieval uses in-process FAISS/NumPy. Fake text generation cannot
  substitute for embedding vectors.
- Tests in `tests/unit/test_fraud_rag.py` use an injected deterministic
  lexical embedder.
