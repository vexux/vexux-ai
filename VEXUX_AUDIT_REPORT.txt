3. API route and fraud-specific call path
-----------------------------------------
CONFIRMED: API ROUTE
- api.main.get_agent() returns core.composition.create_agent().
- POST /api/v1/agent/run injects that generic agent through get_agent() and
  run_agent() calls agent.run(query, session_id, user_id).
- AgentRunRequest contains optional workflow, agent, and delegations fields,
  but run_agent() does not forward these fields.
- The generic composition registers KnowledgeGroundedAnswerWorkflow, not
  FraudInvestigationWorkflow. Therefore, the current API endpoint does not
  construct the fraud-specific demo or real composition.
- FastAPI's default interactive documentation route is /docs.
- API request handling emits request audit events and redacts serialized
  output, but does not authenticate the requestor.

4. Dependency audit: import path and minimum packages
-----------------------------------------------------
CONFIRMED: IMPORT AND CALL PATH
1. Importing apps.fraud.demo imports core.composition plus fraud workflow,
   graph, policy, investigation, SQLite-source and standard-library modules.
2. Importing core.composition imports rag.pipeline. rag.pipeline imports
   rag.vectorstore, which unconditionally imports faiss and numpy. As a result,
   importing the demo module reaches FAISS and NumPy even if no RAG query will
   be made and the fake provider is selected.
3. On entering create_demo_agent(), the factory selects fake only if
   MODEL_PROVIDER was not already set in the process environment; otherwise
   it preserves the caller's provider. It calls core.composition.create_agent().
4. create_agent() calls core.config.get_config(); configuration imports
   python-dotenv and its loader may read the repository .env at runtime.
   This audit did not inspect .env.
5. If provider is fake, create_agent() imports FakeProvider; optional provider
   branches import provider-specific libraries only when selected.
6. create_agent() constructs and registers RAGPipeline but does not retrieve
   documents or call the embedding model at construction time.
7. create_demo_agent() adds temporary SQLite and synthetic graphs, then
   registers FraudInvestigationWorkflow.
8. For "Investigate C1001", workflow planning selects the deterministic fraud
   workflow. The workflow accesses the in-memory graph registry and SQLite
   backend. Python sqlite3 is part of the standard library.

CONFIRMED: SMALLEST DEFENSIBLE EXTERNAL DEPENDENCIES
- `faiss-cpu==1.15.0`: listed in requirements.txt; imported unconditionally
  through rag.vectorstore on the demo import path.
- `numpy`: imported directly in rag.vectorstore, but not separately pinned in
  requirements.txt. Exact compatible version was not verified. It should be
  declared explicitly in a minimal dependency manifest even if a resolver
  currently brings it in transitively.
- `python-dotenv==1.1.1`: listed in requirements.txt; imported by core.config
  and used during create_agent configuration loading.
- Python standard library: includes sqlite3, tempfile, pathlib and other
  modules used by the direct synthetic demo; these are not pip dependencies.

INFERENCE / LIMITS
- The above is the smallest defensible direct third-party set visible from the

  supported platform wheels, exact NumPy compatibility, and a successful run
  were not verified.
- The operational direct call does not itself need FastAPI, Pydantic, Uvicorn,
  HTTPX, pytest, or API-serving packages. They are relevant for API/test runs,

- This repository has no separate minimal-runtime requirements file, pyproject,
  setup.py/setup.cfg, Pipfile, Poetry lock, uv lock, or environment.yml.

5. Synthetic demo configuration and RAG risks
----------------------------------------------
CONFIRMED
- The synthetic demo factory uses fake only when MODEL_PROVIDER is absent from
  the process environment. If another provider is explicitly set, the factory
  preserves it. To target the fake path reliably, the caller must explicitly
  select fake.
- create_agent() conditionally constructs Neo4jKnowledgeGraph when
  config.neo4j_uri is nonempty. This occurs before create_demo_agent() replaces
  the graph registries with synthetic graphs. Therefore, the synthetic factory
  does not unconditionally avoid the Neo4j Python package: a configured
  NEO4J_URI can cause Neo4j driver construction and require the neo4j package.
- No MySQL backend is built by the synthetic demo or generic create_agent()
  path. The MySQL package/service is not needed for this path.
- If no Neo4j URI is configured, Ollama is not selected, and fake is selected,
  the synthetic workflow itself uses no Neo4j, MySQL, Ollama, Transformers,
  PEFT, PyTorch, Sentence Transformers, or embedding assets.
- FAISS and NumPy remain required for import because RAG/vectorstore modules
  are imported eagerly. Thus “fake provider” does not remove all RAG
  dependencies.
- First retrieval calls RAGPipeline._ensure_initialized(), loads local
  documents, embeds them with default BAAI/bge-small-en-v1.5, and builds an
  in-memory FAISS index. If the model is not cached, the embedding library may
  need network access to download it.
- ENABLE_LOCAL_RAG_INFERENCE controls the optional local text-generation
  branch in RAGPipeline.ask(); it does not prevent embedding initialization
  during retrieve().
- Operational investigation requests route to the fraud workflow and do not
  require RAG retrieval. General policy questions can route through RAG and
  therefore can trigger embedding model loading/download.
- create_demo_agent() creates a temporary business SQLite file. Fraud workflow
  audit events also invoke best-effort persistent observability storage, whose
  default path is data/observability/vexux_observability.db; this may create a
  directory/database on the first event. This write was not executed in audit.

CORRECTED / QUALIFIED FROM THE PRIOR REPORT
- Earlier wording that the synthetic demo “does not require Neo4j” was too
  categorical. The workflow's selected data is synthetic and does not use a
  Neo4j service, but core.composition may instantiate the Neo4j adapter before
  the demo replaces its graph registry if NEO4J_URI is configured.
- The actual .env and process environment were not inspected, so whether this
  conditional adapter is triggered on a particular machine is unknown.
- To keep setup independent of Neo4j package/config, explicitly ensure the
  process configuration has no nonempty NEO4J_URI before creating the demo.
  This report does not execute or prescribe a value copied from .env.

7. Security, evidence and auditability
--------------------------------------
CONFIRMED
- Fraud workflows authorize named graph and business-data resources before
  I/O, validate against a small actor allowlist, and collect bounded evidence.
- The fraud default actor is support_user; that actor is denied fraud_graph
  access. investigator is the intended authorized demo actor.
- This application policy is not HTTP authentication. The API accepts
  caller-supplied user_id and does not verify its identity.
- The generic DefaultPolicy is permissive for execution by default; fraud
  checks are application-level behavior.
- API responses and audit metadata redact some sensitive-looking values;
  evidence is bounded and redacted. Audit events are persisted locally to
  SQLite on a best-effort basis, not demonstrated as tamper-proof enterprise
  audit.
- docs/SETUP.md describes database schema/seed commands. It warns seeded data
  is preserved, so running against an existing database can change it.
- Some docs show loopback API binding; other examples use 0.0.0.0. Any
  non-loopback exposure needs explicit company approval.
- Documented/local default ports include API 8000, Ollama 11434, Neo4j 7687,
  and MySQL 3306. Availability and company firewall policy are unknown.

9. Blockers, unknowns, and recommended next step
------------------------------------------------
BLOCKERS BEFORE AN HTTP FRAUD DEMO
1. POST /api/v1/agent/run constructs the generic agent, not the synthetic
   fraud-demo agent; its optional workflow field is not forwarded.
2. No API-to-fraud integration test proves the desired endpoint behavior.
3. Uvicorn is absent from the dependency manifests used by the documented
   API startup command.
4. NumPy is imported directly but not explicitly pinned; no minimal runtime
   manifest exists.
5. Neo4j package construction is conditional on NEO4J_URI in generic
   composition, even though the demo replaces its graph registry afterward.
6. API user identity is unauthenticated and caller-controlled.
7. RAG retrieval may require downloading BAAI/bge-small-en-v1.5. Fake provider
   alone does not avoid this. FAISS/NumPy imports remain eager even without
   retrieval.

UNRESOLVED
- Whether the endpoint should use synthetic demo or real local Neo4j/MySQL.
- Whether Phi-3/Ollama are required for the intended demo or are installed,
  cached, and approved.
- Laptop Python/package compatibility, installation permissions, download
  policy, memory/disk availability, and service/port policy.
- Whether another branch, commit, or repository was intended.
- Whether the direct synthetic demo works on the target laptop. It was not run.

SAFEST MINIMAL SYNTHETIC DEMO PATH — RECOMMENDATION
- Invoke apps.fraud.demo.create_demo_agent() directly, explicitly select
  MODEL_PROVIDER=fake, and call
  agent.run("Investigate C1001", user_id="investigator") inside the context.
- Ensure no nonempty NEO4J_URI reaches core.composition.create_agent(), since
  that generic composition can construct a Neo4j adapter before the demo
  installs synthetic graphs.
- Keep requests to operational fraud workflow types to avoid RAG embedding
  initialization. Account for the local observability SQLite write on the
  first audit event. This is a direct local path, not the current HTTP API.
- The proposed minimal direct-call dependencies are python-dotenv==1.1.1,
  faiss-cpu==1.15.0, and an explicitly chosen compatible NumPy version;
  this set is static analysis only and has not been installed or validated.

PROPOSED MINIMAL PATCH — NOT IMPLEMENTED
- Add an explicit synthetic-fraud API composition with lifecycle-safe
  management of create_demo_agent()'s context and temporary resources; keep
  generic and real Neo4j/MySQL compositions explicit and separate.
- Establish a trusted actor source instead of trusting request user_id.
- Add Uvicorn and an explicit compatible NumPy pin to an approved runtime
  dependency strategy; consider a dedicated minimal-runtime manifest rather
  than installing the training/ML stack for this demo.
- Add an API-to-synthetic-fraud integration test proving an operational

- Document that general RAG retrieval may need the BGE model download and that
